# Административное управление доступом

> **Версия:** 2.0
> **Дата:** 26.08.2026
> **Статус:** реализовано через `Entitlement`

## Главное правило

Ручная выдача, продление, приостановка и отзыв изменяют право доступа `Entitlement`. Они не создают фиктивную `Purchase`: таблица покупок остаётся только финансовой историей подтверждённых оплат.

## Операции

Раздел `/admin/access` поддерживает:

- grant — новый активный entitlement с course/tariff/start/expiry;
- extend — изменение срока существующего доступа;
- suspend — временная приостановка;
- revoke — окончательный отзыв.

Для каждой операции обязательны permission, причина и подтверждение опасного действия. Backend записывает actor, object, old/new values, reason, timestamp и correlation ID в `AuditLog`. Повтор запроса не должен создавать дублирующий финансовый объект.

## Срок

Текущий курс использует 30 дней, но срок задаётся в `Course.access_days` и фиксируется в `Order`. При ручной выдаче оператор явно выбирает дату окончания; интерфейс не обещает 365 дней.

## Проверка результата

1. В карточке ученика появился entitlement с правильными курсом, источником, статусом и сроком.
2. Покупка не создалась, если денег не было.
3. Урок доступен только пока entitlement active и не истёк.
4. Операция появилась в audit log с причиной/correlation ID.
5. При необходимости notification отправлено через outbox, а не внутри admin HTTP request.

## Возвраты

Возврат денег оформляется отдельным `RefundRequest`, выполняется в кабинете Prodamus и затем подтверждается provider reference/status в админке. Решение об отзыве/сокращении entitlement выполняется отдельной аудируемой операцией согласно политике возврата.
