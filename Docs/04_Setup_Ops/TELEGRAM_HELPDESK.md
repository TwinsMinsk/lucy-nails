# Бот поддержки в Telegram

Бот школы работает как окно в магазин и как служба поддержки:

- **Покупательницы** пишут боту в личные сообщения: про оплату, доступ, курс. Сайт ведёт к боту из подвала, у кнопки оплаты, со страниц «Оплата прошла / не прошла» и из личного кабинета.
- **Операторы** (владелица и преподаватель) сидят в одной закрытой группе с темами. У каждой покупательницы своя тема: её сообщения появляются там, ответ в теме уходит ей от имени бота.
- В отдельной теме **«Оплаты»** бот сообщает о каждом заказе: создан, оплачен, оплата не прошла, не оплачен через час, возврат, аккаунт активирован. В каждом сообщении email покупательницы и номер заказа.

Бот получает сообщения через вебхук бэкенда (`POST /api/telegram/webhook`), отдельный процесс бота в production не нужен.

## Что работает сразу после выкладки, до настройки

Пока шаги ниже не выполнены (нет группы, переменных и вебхука):

- Уведомления «🧾 Новый заказ», «⏳ Заказ не оплачен» и «🔑 Аккаунт активирован» приходят вместе с прежними уведомлениями об оплатах в личный чат владелицы (`TELEGRAM_OWNER_CHAT_ID`).
- **Первый проход воркера после выкладки** может прислать сразу пачку сообщений и про заказы, созданные ещё до выкладки:
  - до 50 «🧾 Новый заказ» по неоплаченным заказам за предыдущие 24 часа, по которым такого уведомления ещё не было (до выкладки его не было ни у одного заказа); оплаченные заказы не присылаются — о них уже было «💰 Новая оплата»;
  - «⏳ Заказ не оплачен» по неоплаченным заказам, чей возраст в этот момент попадает в окно от N до 2N минут (`ORDER_ABANDONED_ALERT_MINUTES`, по умолчанию 60–120 минут), до 50 за проход.

  Каждый заказ сообщается не больше одного раза каждого вида; дальше уведомления идут по мере появления новых заказов.
- Бот покупательницам **ещё не отвечает**: вебхук не включён, а отдельного процесса бота в production нет.
- Ссылки на сайте (подвал, строка у кнопки оплаты, окно оплаты без регистрации, страницы «Оплата прошла / не прошла», кнопка «Поддержка» в кабинете) уже ведут к боту. Рядом с ними везде, где платят, стоит почта поддержки Luci4ek@gmail.com — она работает с первого дня.
- В письме «Срок доступа завершён» остаётся прежний контакт в Telegram; на бота письмо переключится само, когда будет задан `TELEGRAM_HELPDESK_CHAT_ID`.

## Что понадобится

- Доступ к Railway (сервисы Backend, Worker, Frontend).
- Бот уже создан в BotFather, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` заданы на Backend и Worker.

## 1. Создать группу операторов

1. В Telegram: «Новая группа», добавить преподавателя и бота (по username, например `@lucynails_bot`). Название любое, например «Поддержка Lucy Nails».
2. Группа должна быть **частной** (без публичной ссылки). Никого, кроме операторов, в неё не добавлять: в темах видны email и заказы покупательниц.
3. Настройки группы → **«Темы» → включить**. Группа станет супергруппой с темами, это нормально.

## 2. Сделать бота администратором

Настройки группы → «Администраторы» → «Добавить администратора» → бот. Нужны права:

- **«Управление темами»** — обязательно: бот создаёт, переименовывает, закрывает и открывает темы.
- Отправка сообщений у администраторов есть всегда.

Остальные права боту не нужны. Администратор получает все сообщения группы, поэтому режим приватности бота (privacy mode в BotFather) менять не нужно.

## 3. Создать тему «Оплаты»

В группе: «Создать тему» → название **«Оплаты»**. Сюда будут приходить уведомления о заказах. Сообщения в этой теме и в «Общем» (General) бот никому не пересылает — там можно обсуждать что угодно.

## 4. Включить вебхук

1. Придумать секрет вебхука: 32–256 символов из латиницы, цифр, `_` и `-`. Проще всего сгенерировать:

   ```powershell
   python -c "import secrets; print(secrets.token_urlsafe(36))"
   ```

   Секрет никому не пересылать и никуда не записывать, кроме Railway.
2. Railway → сервисы **Backend** и **Worker** → Variables → `TELEGRAM_WEBHOOK_SECRET` = секрет. Дождаться деплоя Backend.
3. Сообщить Telegram адрес вебхука. Скрипт берёт токен, секрет и `BACKEND_URL` из переменных сервиса и не печатает ни токен, ни секрет:

   ```powershell
   railway ssh --service Backend
   python scripts/telegram_webhook.py set
   python scripts/telegram_webhook.py info
   ```

   Команды выполняются в каталоге приложения Backend (там лежат `app/` и `scripts/`). В ответе `set` должен быть адрес `https://<домен API>/api/telegram/webhook`, в `info` — тот же `url` и пустой `last_error_message`. Если `railway ssh` недоступен, то же самое можно запустить локально из корня репозитория, передав `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `BACKEND_URL` через переменные окружения: `python backend/scripts/telegram_webhook.py set`.

Telegram передаёт обновления по одному, поэтому сообщения покупательницы приходят в тему в том порядке, в каком она их написала. Неотправленные обновления, накопившиеся до включения, не теряются.

## 5. Узнать id группы и темы

Вебхук уже работает, поэтому бот отвечает на команду `/chatid` в любом чате:

1. В группе, в теме «Общее» (General), отправить `/chatid` → бот ответит `ID чата: -100…`. Это **id группы**.
2. В теме «Оплаты» отправить `/chatid` → бот ответит id чата и `ID темы: …`. Это **id темы «Оплаты»**.

## 6. Задать переменные в Railway

На сервисах **Backend** и **Worker** (Variables):

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_WEBHOOK_SECRET` | секрет из шага 4 (уже задан) |
| `TELEGRAM_HELPDESK_CHAT_ID` | id группы из шага 5 (с минусом) |
| `TELEGRAM_HELPDESK_ALERTS_TOPIC_ID` | id темы «Оплаты» из шага 5 |
| `ORDER_ABANDONED_ALERT_MINUTES` | через сколько минут неоплаченный заказ попадёт в «Оплаты»; по умолчанию 60, `0` — не сообщать |

Дождаться деплоя обоих сервисов. Если у бота username не `lucynails_bot`, на сервисе **Frontend** задать `NEXT_PUBLIC_SUPPORT_BOT_USERNAME` (без `@`) и пересобрать Frontend — иначе ссылки на сайте поведут не туда.

После этого уведомления владелице идут в тему «Оплаты», а не в личный чат (`TELEGRAM_OWNER_CHAT_ID` остаётся запасным: если убрать id группы или темы, уведомления вернутся туда).

## 7. Проверить

1. С личного аккаунта (можно своего) открыть бота и нажать «Старт» → бот здоровается и просит email, указанный при покупке.
2. Написать любое сообщение → бот отвечает «Спасибо! Сообщение передано в поддержку…», в группе появляется тема с именем отправителя и карточкой клиента, следом — само сообщение.
3. В этой теме ответить текстом → ответ приходит в личку от бота.
4. В теме отправить `/info` → свежая карточка. Отправить `/close` → тема закрывается; написать боту ещё раз → тема открывается сама.
5. Оформить тестовый заказ на сайте (без оплаты) → в «Оплатах» появляется «🧾 Новый заказ».

## Как работать в темах

- **Ответ клиенту** — обычное сообщение в её теме: текст, фото, файл, голосовое. Можно ответить «ответом» на конкретное её сообщение — у неё оно тоже будет ответом. Если бот не смог доставить ответ (клиент заблокировал бота или ни разу ему не писал), в теме появится «⚠️ Сообщение не доставлено…».
- **Команды** (в теме клиента; сообщения со `/` клиенту не уходят):
  - `/info` — свежая карточка: имя, @username и id в Telegram; аккаунт на сайте или email, который клиент написал сам (помечен «не подтверждён»), или «аккаунт не найден»; до пяти последних заказов (дата по Москве, курс, сумма, статус: не оплачен / оплачен / возврат); текущий доступ и дата окончания или «доступа нет». Если клиент пришёл по ссылке со страницы оплаты, этот заказ стоит первым с пометкой.
  - `/close` — закрыть тему и обращение. Новое сообщение клиента откроет их снова.
  - `/block` — заблокировать клиента (спам, грубость): его сообщения больше не приходят, бот ему ничего не отвечает. `/unblock` — разблокировать.
  - `/chatid` — id чата и темы (работает в любом чате).
- **Email в карточке.** Клиент может прислать email текстом — бот запишет его в карточку как «не подтверждён» и переименует тему. Клиенту бот никогда не сообщает ничего об аккаунте, заказах или доступе: проверяет и отвечает оператор.
- **Сколько отвечает бот сам.** Только приветствие на «Старт», подтверждение «сообщение передано» (на первое сообщение и потом не чаще раза в три часа) и просьбу подождать, если клиент шлёт больше 20 сообщений или команд в минуту (лишние отбрасываются, включая повторные «Старт»).

## Уведомления в «Оплатах»

| Сообщение | Когда |
| --- | --- |
| 🧾 Новый заказ | клиент нажал «Оплатить» (сумма, курс, email, источник и кампания UTM, номер заказа) |
| 💰 Новая оплата | платёж подтверждён, доступ выдан |
| ℹ️ Неуспешная попытка оплаты / ⚠️ Платёж не обработан | банк отклонил платёж или вебхук не принят; email заказа и, если отличается, email из формы оплаты |
| ⏳ Заказ не оплачен | заказ не оплачен через `ORDER_ABANDONED_ALERT_MINUTES` минут (один раз; бот смотрит только заказы возрастом от N до 2N минут: более старые неоплаченные заказы не сообщаются, а заказы из этого окна сообщаются, даже если созданы до выкладки; не сообщается, если клиент после создания этого заказа оплатил тот же курс — считается время оплаты, а не время другой ссылки) |
| 🔑 Аккаунт активирован | покупатель задал пароль по ссылке из письма |
| ↩️ Возврат оформлен | возврат проведён в админке (сумма, email, курс) |
| ⚠️ Повторная оплата заказа, ⚠️ не доставлено уведомлений | как раньше |

Номер заказа выглядит как `order|<uuid>` — по нему заказ ищется в админке и в карточке клиента.

## Как выключить

- **Только поддержку:** одним изменением удалить `TELEGRAM_HELPDESK_CHAT_ID` и `TELEGRAM_HELPDESK_ALERTS_TOPIC_ID` на Backend и Worker (тему без группы конфигурация не принимает). Бот будет отвечать клиентам, что поддержка работает по почте Luci4ek@gmail.com; уведомления вернутся в чат `TELEGRAM_OWNER_CHAT_ID`.
- **Уведомления о неоплаченных заказах:** `ORDER_ABANDONED_ALERT_MINUTES=0`.
- **Всё целиком (вебхук и поддержку).** Порядок важен: пока задан `TELEGRAM_HELPDESK_CHAT_ID`, Backend, Worker и миграции при старте требуют `TELEGRAM_WEBHOOK_SECRET`, и без секрета не запустятся.
  1. Удалить вебхук в Telegram: `python scripts/telegram_webhook.py delete` (как в шаге 4). Бот перестаёт получать сообщения сразу.
  2. Одним изменением конфигурации на **Backend и Worker** удалить все три переменные: `TELEGRAM_HELPDESK_CHAT_ID`, `TELEGRAM_HELPDESK_ALERTS_TOPIC_ID` и `TELEGRAM_WEBHOOK_SECRET` (в Railway — изменить переменные обоих сервисов и применить изменения разом, не по одной с деплоем после каждой).
  3. Развернуть оба сервиса. Адрес вебхука начнёт отвечать 404, уведомления вернутся в `TELEGRAM_OWNER_CHAT_ID`, письмо об окончании доступа — на прежний контакт.

  Привязка Telegram из личного кабинета без вебхука тоже перестанет работать.

## Если что-то не так

- `python scripts/telegram_webhook.py info` показывает `pending_update_count` и `last_error_message`. «403 Forbidden» — секрет в Railway не совпадает с заданным в Telegram: повторить `set`. «503» — временная ошибка (база, сеть), Telegram повторит доставку сам.
- Если тему клиента удалили вручную, бот создаст новую при следующем сообщении клиента.
- При сбое сети в момент пересылки Telegram повторит доставку, а бот не перешлёт сообщение второй раз. Если исход неизвестен (связь оборвалась уже после отправки), в теме появится «⚠️ Сбой связи с Telegram: не уверены, что … дошло» — проверьте и при необходимости попросите повторить. В редком случае сбой при создании темы может оставить пустую тему — её можно удалить.
- Если Telegram окончательно отказался переслать сообщение клиента, клиент получает просьбу повторить или написать на почту, а операторы — «⚠️ Сообщение клиента не удалось переслать…» в его теме или, если темы нет, в «Общем».

## Для разработчиков

- Обработка обновлений: `backend/app/services/telegram_helpdesk_service.py`, вебхук: `backend/app/api/telegram_webhook.py`, уведомления: `backend/app/services/owner_alerts.py`.
- Локально бот запускается через long polling (`.\scripts\run_bot.ps1`) тем же кодом. Polling не работает, пока у бота задан вебхук: для локальной разработки нужен отдельный тестовый бот, вебхук production-бота не удалять.
