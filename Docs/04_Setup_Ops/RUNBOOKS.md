# Операционные runbook’и

Каждый инцидент получает владельца, severity, время начала, correlation ID, затронутые order/user ID без платёжных данных и итоговую причину. Секреты и сырые webhook payload в тикет не копируются.

## Платёж есть, доступа нет (P0)

1. В «Аудит и система» немедленно отключить checkout с причиной — deploy не нужен; webhook остаётся доступен.
2. Найти заказ, `PaymentEvent`, покупку, entitlement и outbox по order/payment ID.
3. Сверить сумму/валюту и статус с Prodamus. Не выдавать доступ по скриншоту клиента.
4. После подтверждения создать/исправить entitlement идемпотентной админ-операцией и повторить уведомление.
5. Проверить другие события за тот же период, устранить причину, включить checkout с причиной.

## Webhook не обрабатывается (P0)

Проверить `/health`, последний webhook, подпись, URL Prodamus, PaymentEvent errors и логи по correlation ID. Не отключать endpoint. При накоплении платежей отключить только создание новых checkout. После исправления повторить события из официального кабинета/документированного источника и провести reconciliation.

## Письмо или Telegram не доставлены (P1)

Открыть «Уведомления», проверить channel/status/last_error. Исправить provider credentials, затем выполнить ручной retry с причиной. Не отправлять активационный token в открытый чат. Для истёкшей ссылки создать новую через штатный flow.

## Видео недоступно (P1)

В «Курсы» запустить «Проверить видео». Проверить video ID, provider status, DRM backend, domain/privacy settings и активный entitlement тестового ученика. Не заменять production-видео публичной ссылкой. Если массовый сбой Kinescope — показать уведомление ученикам и зафиксировать компенсационное продление.

## Возврат

Создать заявку в админке, проверить покупку и допустимую сумму. Финансовую операцию выполнить в официальном кабинете Prodamus. Затем записать provider reference/status, отозвать или скорректировать доступ по принятой политике и проверить net revenue.

## Откат deploy

Остановить новые checkout при риске платежей. Откатить приложение на предыдущий проверенный Railway deploy. Миграцию откатывать только если её downgrade протестирован и новый код больше не пишет новые поля. После отката: health, вход, admin, webhook, outbox и один demo smoke.

## Утечка секрета (P0)

Сначала отозвать и ротировать затронутый ключ у провайдера, затем обновить environment variables и перезапустить соответствующие процессы. Для JWT/password risk принудительно завершить сессии. Проверить audit/provider logs, удалить секрет из истории отдельной процедурой и зафиксировать затронутый период.

## Восстановление БД

Следовать `BACKUP_RESTORE.md`. Сначала restore drill, затем согласованное production-восстановление. Checkout до reconciliation остаётся выключенным.
