# PRD: Lucy Nails Academy — production release

> **Версия:** 2.0
> **Дата:** 26.08.2026
> **Статус:** код релиза реализован; запуск заблокирован внешними go-live проверками
> **Источник текущего статуса:** [`audit/production-readiness-2026-08-26/README.md`](audit/production-readiness-2026-08-26/README.md)

## 1. Цель релиза

Lucy Nails Academy продаёт один практический видео-курс, автоматически выдаёт ограниченный по времени доступ после подтверждённой оплаты и даёт команде единый административный контур для клиентов, контента, денег, уведомлений и аналитики.

Цель production release — безопасно принять до 500 учеников при ориентире около 100 одновременных пользователей. PostgreSQL является источником истины для заказов, оплат, доступов и учебной аналитики.

## 2. Фактический продукт

Публичный production API на 26.08.2026 сообщает:

| Параметр | Фактическое значение |
|---|---|
| Курс | Nail Design PRO: 11 продающих техник для мастера |
| Модули / уроки | 11 / 11 |
| Длительность | 17 136 секунд — 4:45:36 |
| Самостоятельный тариф | 5 900 ₽ |
| Тариф с поддержкой | 11 900 ₽ |
| Срок доступа | 30 дней; поле курса настраивается администратором |
| Домашние задания | не входят в релиз |

Цена, валюта, тариф, курс и срок доступа фиксируются в `Order` при начале checkout. Изменение курса после этого не меняет уже созданный заказ.

## 3. Пользователи и ключевые сценарии

### Ученик

- Просматривает лендинг, программу, примеры работ, тарифы и юридические документы.
- Начинает checkout без регистрации либо из существующего аккаунта.
- Переходит в Prodamus и получает доступ только после валидного webhook с совпадающими суммой, валютой и заказом.
- Новый пользователь получает одноразовую ссылку установки пароля на 24 часа; известный системе случайный пароль не создаётся.
- На странице успешной оплаты видит реальный статус: ожидание, оплачено и доступ открыт, либо обращение в поддержку.
- Смотрит защищённые уроки Kinescope, сохраняет прогресс, завершает курс и получает сертификат.
- Может привязать Telegram одноразовой ссылкой и получать уведомления об оплате, доступе и окончании срока.

### Владелец и команда

- `owner` управляет ролями, критическими операциями и настройками; последнего owner удалить нельзя.
- `admin` выполняет операционную работу с пользователями, заказами, доступами и контентом.
- `content_manager` управляет только курсом, уроками, лендингом и медиа.
- `curator` работает с учениками, прогрессом и доступами в пределах разрешений.
- `analyst` получает read-only отчёты с маскированными персональными данными.
- Для owner/admin обязательна TOTP MFA; доступны резервные коды, активные сессии и принудительный logout.

## 4. Commerce и доступ

Каноническая цепочка:

```text
Checkout → immutable Order → Prodamus → signed PaymentEvent
         → Purchase (финансовая история) → Entitlement (право доступа)
         → OutboxMessage → email / Telegram → DeliveryAttempt
```

Обязательные инварианты:

1. Редирект на success page не подтверждает оплату.
2. Webhook проверяет подпись, успешный статус, сумму и валюту по снимку `Order`.
3. Повторные и одновременные события идемпотентны и журналируются в очищенном виде.
4. Оплата, покупка, доступ и outbox фиксируются одной транзакцией.
5. Ручная выдача создаёт `Entitlement`, а не фиктивную покупку.
6. Checkout можно немедленно выключить из админки без deploy; уже начатые webhook продолжают приниматься.
7. Возврат ведётся как заявка и история внутри системы, а деньги возвращаются в официальном кабинете Prodamus.

## 5. Административный контур

Релиз включает разделы:

- «Главная»: продажи, gross/refund/net revenue, новые ученики, ошибки оплат, outbox и быстрые действия.
- «Пользователи»: серверный поиск, пагинация, покупки, доступы, прогресс, сертификаты, заметки и теги.
- «Заказы и оплаты»: заказы, PaymentEvent, расхождения, возвраты, CSV и повторная доставка.
- «Доступы»: выдача, продление, приостановка и отзыв с обязательной причиной.
- «Курсы»: модули, уроки, публикация, порядок, цены, срок доступа и проверка Kinescope ID/status/duration.
- «Лендинг»: тексты, галерея, изображения и preview.
- «Прогресс»: активность, незавершённые уроки, завершение и истекающие доступы.
- «Сертификаты»: реестр, скачивание, повторная выдача, отзыв и история.
- «Уведомления»: email/Telegram outbox, попытки, dead letter и ручной retry.
- «Аналитика»: временные ряды, воронка, источники, тарифы, когорты, вовлечённость, возвраты и доставка.
- «Аудит и система»: роли, сессии, MFA, интеграции, журнал действий и checkout kill switch.

Все опасные изменения имеют permission check, обязательную причину и запись в `AuditLog` с correlation ID.

## 6. Аналитика и согласие

First-party события: landing view, CTA, checkout start, redirect, paid, account activation, lesson start/complete, course complete, certificate, expiry и refund. Сервер создаёт финансовые и учебные события; email и платёжные данные в события не копируются.

Заказ хранит first-touch и last-touch UTM. Gross/refund/net revenue считаются только по подтверждённым серверным операциям. Яндекс Метрика включается только на публичных страницах после согласия категории «аналитика»; кабинет и админка не отслеживаются.

## 7. Telegram и доставка

- Привязка Telegram одноразовая, короткоживущая и хранится в виде хеша.
- Email и Telegram используют общую durable outbox с retry и dead-letter.
- Напоминания отправляются за 7/3/1 день до окончания; после окончания можно удалить ученика из support group.
- Владелец получает алерты о webhook/outbox/integration/backup ошибках при настроенном owner chat.

## 8. Нефункциональные требования

- Python 3.11, PostgreSQL 15, Redis для общего rate limit, Node.js 20+, Next.js 16.
- Cookie auth между `lucysmirnova.ru` и `api.lucysmirnova.ru`, CSRF для изменяющих запросов, строгие CORS/trusted hosts/CSP.
- Секреты только в environment variables; в логах нет query string, email, платёжных payload или токенов.
- Структурированные request logs с correlation ID.
- Ежедневный backup, отдельная еженедельная зашифрованная копия, RPO ≤ 24 ч и RTO ≤ 4 ч.
- Gate нагрузки: ошибки < 1%, внутренний API p95 < 500 мс при 100 чтениях, 20 одновременных checkout и 10 webhook/с.
- Критические пользовательские потоки соответствуют WCAG 2.2 AA.

## 9. Go-live критерии

Запуск разрешён только когда:

- нет открытых P0/P1 в датированном аудите;
- staging изолирован и прошёл полный smoke;
- один реальный платёж и возврат подтверждены end-to-end;
- доступ появляется ≤ 60 секунд, уведомление ≤ 2 минут;
- все 11 уроков проверены на desktop, iOS и Android с DRM и истечением доступа;
- production secrets, Redis, worker, bot, email и алерты проверены;
- внешний encrypted backup восстановлен в отдельную БД;
- нагрузочный gate пройден;
- оферта, privacy/cookie policy, согласия, возвраты, чеки и налоговые настройки согласованы российским юристом/бухгалтером.

## 10. Не входит в этот релиз

Домашние задания и проверка работ, универсальная LMS, промокоды, рассрочки, marketplace курсов, мобильное приложение и расширение курса сверх текущих 11 уроков.
