## Целостность слоёв / god-роутер

### BE-03 — `admin.py` (797 строк): god-router с протёкшей бизнес-логикой · MED · чистый рефакторинг
- CRUD для users/courses/modules/lessons + analytics + grant-access в одном файле.
- Бизнес-логика в хендлерах: ручная сборка ответов с подсчётом уроков `admin.py:239-255`; bulk-`setattr(course, key, value)` при апдейте; логика выдачи доступа (`grant-access`) формирует «admin»-`payment_id` прямо в роутере, минуя `PurchaseService`.
- Рекомендация: вынести в доменные admin-сервисы (как уже сделано для `lesson_service`, `purchase_service`). **Поведение не меняется.** Совпадает с уже зафиксированным техдолгом (`CODEBASE.md:56`).

### BE-04 — Нарушение слоёв импорта гарда · LOW · чистый рефакторинг

## Async-корректность

### BE-01 — Блокирующий I/O в async-роуте загрузки · MED · чистый рефакторинг
- `upload.py:82-84`: `contents = await file.read()` затем синхронный `with open(file_path,"wb") as f: f.write(contents)` — блокирует event loop на время записи.
- Смягчающие факторы: эндпоинт только для админов и отключён в production без настроенного хранилища (`upload.py:55-59`).
- Исправление: `await asyncio.to_thread(...)` или `aiofiles`. **Поведение не меняется** (только конкурентность).

### BE-06 — Авто-commit в `get_db` (наблюдение, НЕ дефект) · меняет поведение если трогать
- `core/database.py:43`: сессия коммитит при успешном выходе из хендлера. Это осознанная политика (CLAUDE.md прямо запрещает точечные правки без сверки). Риск: «тихий» commit при логической ошибке, не сделавшей rollback. **Не править без отдельного решения** — внизу backlog.

### N+1 / eager-loading
- В основном корректно (`selectinload` в `admin.py:232-234` и др.). Явных N+1 в горячих путях не обнаружено. Ручной подсчёт `sum(len(m.lessons) ...)` в `admin.py:241` работает на уже eager-загруженных данных — не N+1, но кандидат на SQL-агрегацию при росте объёмов (LOW).

## Pydantic v2 / валидация
- Схемы и модели разделены (`schemas/` vs `models/`). Вебхук Prodamus валидирует email через `TypeAdapter(EmailStr)` (`payments.py:49-62`), телефон — `_normalize_phone` (`payments.py:39-46`). Гостевой эндпоинт типизирован `EmailStr`/`Literal` (`payments.py:320-324`).
- Наблюдение (LOW): часть admin-эндпоинтов строит ответы вручную вместо `response_model` (см. BE-03) — снижает контрактную строгость OpenAPI.

### BE-02 — `datetime.utcnow()` (deprecated в Py 3.12+) · LOW · чистый рефакторинг
- `payments.py:270`, `dependencies.py:112` (и др.). Заменить на `datetime.now(timezone.utc)`. Особенно важно с учётом локального Python 3.14 (см. [05-tests-ci.md](05-tests-ci.md)).

## Auth / rate-limit
- Гарды корректны: `get_current_user` принимает токен из заголовка **или** cookie (`dependencies.py:47`), отклоняет refresh-токен в access-пути (`dependencies.py:57`), грузит пользователя из БД. `require_admin` (`:72`) и `require_course_access` (`:89`) — на месте. **Обходных путей не найдено.**
- Rate-limit: глобальный дефолт `200/minute` применяется ко **всем** маршрутам через `SlowAPIMiddleware` (`rate_limit.py:6` + `main.py:122`); на чувствительных эндпоинтах — строже (`auth` 15–45/min, `payments` 20–120/min, `kinescope drm` 600/min).
- ⚠️ Ограничение масштабирования (не дефект): лимитер in-memory (`get_remote_address`), для мульти-инстанса нужен Redis-backend — уже в `POST_MVP_HARDENING`.
